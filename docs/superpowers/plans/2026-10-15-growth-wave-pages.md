# Growth Wave Home & Contact Pages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Growth Wave's Home and Contact Us pages as a bilingual (Arabic RTL / English LTR) Next.js 16 app that meets all five acceptance criteria of the AIHI brief.

**Architecture:** App Router with a `[locale]` root segment (next-intl, always-prefixed, Arabic default). Pages are statically generated Server Components with a few client islands. All copy lives in `src/messages/{ar,en}.json` and all structure (hrefs, ids, icons, images) in typed `src/content/*.ts`. The contact form uses react-hook-form with a zod schema shared with a mock Route Handler.

**Tech Stack:** Next.js 16.4 · React 19.3 · TypeScript (strict) · Tailwind CSS 4.3 · shadcn/ui 4.21 (Radix, RTL mode) · next-intl 4.14 · react-hook-form 7.90 · zod 4.6 · @hookform/resolvers 5.9 · sonner 2 · lucide-react 1.57 · Vitest 5 · Playwright 1.64 · pnpm 11 · Node 24

**Spec:** `docs/superpowers/specs/2026-10-15-growth-wave-design.md`

## Global Constraints

- Package manager **pnpm** (`"packageManager": "pnpm@11.22.0"`), Node 24, TypeScript `strict`, import alias `@/*` → `src/*`.
- Locales `['ar', 'en']`, `defaultLocale: 'ar'`, `localePrefix: 'always'`; `ar` → `<html dir="rtl">`, `en` → `dir="ltr"`, set server-side.
- **No user-visible string literals in components.** Copy comes from `src/messages/{ar,en}.json` (Appendix A/B); structure comes from `src/content/*.ts`.
- Tailwind **logical utilities only** (`ms-/me-/ps-/pe-/start-/end-/text-start/text-end`); never `ml-/mr-/pl-/pr-/left-/right-/text-left/text-right`. Directional icons flip with `rtl:-scale-x-100`.
- Phone numbers, emails and the email/phone inputs carry `dir="ltr"`.
- Brand tokens (exact): brand `#0047AB`, brand-hover `#003A8C`, navy `#0E3274`, tint-50 `#F5F9FF`, tint-100 `#EBEFFA`, ink `#000A18`, body `#585858`, muted `#6B6B6B`, line `#D4D4D4`. Font **Readex Pro**. Container max-width **1200px**; cards radius `1rem`, buttons/inputs `0.5rem`.
- Server Components by default. Client components only: `HeaderShell`, `NavLinks`, `MobileNav`, `LocaleSwitcher`, `ContactForm`, `Reveal`, `error.tsx` (+ the shadcn primitives they use).
- **No environment variables.** Contact endpoint is `CONTACT_ENDPOINT = '/api/contact'` in `src/lib/contact-service.ts`.
- Raster images via `next/image`; the LCP hero uses **`preload`** (Next 16 replacement for the deprecated `priority`).
- **Zero browser console errors** on every page. Enforced by the e2e fixture from Task 1. A test may allow a specific error only with `test.use({ allowedConsoleErrors: [...] })`.
- Every task ends green on `pnpm lint && pnpm typecheck && pnpm test`, plus its own e2e spec on Chromium. Task 11 runs all three engines.
- Conventional Commits, one commit per task (minimum). Never commit `docs/research/`, `.playwright-mcp/`, test reports or Lighthouse output.

## Deviations from the spec (approved together with this plan)

1. **Images** are statically imported from `src/assets/` (automatic width/height, blur placeholders, hashed URLs) instead of `public/images/`. The PDF stays in `public/files/`.
2. **Coming soon route** is a catch-all `src/app/[locale]/[...slug]/page.tsx`. A single known slug renders Coming soon, and anything else calls `notFound()`, so nested unknown paths (`/en/about/team`) also get the localized 404. Next does not allow a sibling `[slug]` and catch-all.
3. **LocaleSwitcher** is a next-intl `<Link locale=…>` (crawlable, works before hydration) instead of `router.replace`.
4. **Logo** is one component with `fill="currentColor"` (blue in the header, white in the footer). The two Growth Wave logo variants differ only in color.
5. **`tel:` link** uses the international form `tel:+966558045586`. The displayed text stays `0558045586`.
6. **Phone validation** also accepts Arabic-Indic digits (`٠٥٥…`) by converting them to `0–9` before the regex (Review Focus #1).
7. **Name validation** allows Unicode combining marks (`\p{M}`) so vowelled Arabic names like `مُحَمَّد` pass.
8. **Polish:** a "Skip to main content" link; a "(opens in a new tab)" screen-reader hint on new-tab links; Google Maps loads in the page language (`hl=ar|en`). `AGENTS.md`/`CLAUDE.md` generated by create-next-app are removed.

## Review Focus

Input classes the spec implies but would otherwise go untested. Each has a test in the owning task.

1. **Arabic-Indic digits in the phone field** (`٠٥٥٨٠٤٥٥٨٦`, common on Arabic keyboards): accepted and normalized to `0558045586`. Task 8.
2. **Double-clicking Send:** exactly one POST reaches `/api/contact`. Task 9.
3. **Server rejects a field the client accepted** (422 with `fieldErrors`): the error appears on that field and typed values are kept. Task 9.
4. **Returning visitor:** a `NEXT_LOCALE=ar` cookie wins over an English `Accept-Language` when visiting `/`. Task 2.
5. **Nested unknown URL** (`/en/about/team`): returns 404 with the localized Not Found page, not a crash or an untranslated default. Task 10.

```ts
  allowedConsoleErrors: [[], { option: true }],
  consoleErrors: [
    async ({ page, allowedConsoleErrors }, use) => {
      const errors: string[] = [];
      const record = (text: string) => {
        if (!allowedConsoleErrors.some((re) => re.test(text))) errors.push(text);
      };
      page.on('console', (m) => m.type() === 'error' && record(m.text()));
      page.on('pageerror', (e) => record(e.message));
      await use(errors);
      expect(errors, 'browser console errors').toEqual([]);
    },
    { auto: true },
  ],
});
export { expect };
```
